Every card carries, word for word:

**Every fix leaves 1 cheap test, so the same problem never returns:**

- It sits in the cheapest suite that can see the fault, and is seen red on
  the unfixed code first.
- It checks the rule the bug broke — every route, item or input that rule
  covers — and what the user sees: never 1 example, an input, or the code's
  own constant.
- Logic that lives in screen code gets a cheap test of that logic, even when a
  screen test also stays.
- It owns its clock and its order: no real waits, nothing left from the test
  before, so it never goes red with nothing wrong.
- A second fix of the same behaviour first says why the earlier test stayed
  green, and fixes that test.

Each card's first step re-checks its issue as filed; not there after 2 honest tries (the steps as written, then the way a user would) closes it `not reproduced by card <name>, <date>`. Fixed: the file moves to `docs/issues/closed/` with `Closed by: <tag>, card <name>`, and the card says `Closes issue 00NN`. A card that fails fills its issue's `Tried by` line.
