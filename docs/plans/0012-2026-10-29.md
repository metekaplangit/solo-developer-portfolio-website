## A — The first product page a visitor opens draws as soon as it arrives

bump: patch. screen: @home @sole-focus @magic-notes @waypost-words (photographs prove no look changed).

- Outcome: every built page links the same stylesheet set, so after the first page a visitor opens, no page change waits for new CSS.
- Measured by smooth-project 0001 (live, scripts/probe/smooth-probe.mjs drive): home → product, click to first frame 379 ms (Chrome 156, Mac), 386 ms (WebKit 26.4), 573–610 ms (4× CPU, 150 ms RTT, 1.6 Mbps); the HTML response was in at 250 / 97 / 87–115 ms. Every other page change draws 1–15 ms after its response.
- Cause: Vite's CSS code split gives product pages their own render-blocking `dist/_astro/_slug_.*.css` (15 KB); home loads `BaseLayout.*.css` + `index.*.css`, Apps only `BaseLayout.*.css`. The first product page pays one more round trip (+125 ms Mac, +290 ms WebKit, +460 ms slow phone).
- Budget: screen change under 300 ms. Target: first frame within about 20 ms of the HTML response, as every other page change already does — no further.
- Acceptance: every page in `dist/` links exactly the same stylesheet(s); no page looks different (before/after captures); the CSP meta still validates (no style violation in the screen suite); re-measured live after deploy, home → product first frame within ~20 ms of its response in Chrome.
- Touches: `astro.config.mjs` (the `vite` block, or Astro's own equivalent), `tests/dist.test.ts`.
- Must keep working: the look of every page at every width; the CSP `<meta>` and its hashes; total CSS a first visit downloads stays small (report the size before and after).
- Proof: `npm run headless`; `node scripts/rendered.mjs @home @sole-focus @magic-notes @waypost-words`; after deploy `node scripts/probe/smooth-probe.mjs navdetail --from / --to /apps/` style re-drive of home → product.
- Prior art: Vite `build.cssCodeSplit: false` (see Research). Avoid: inlining every stylesheet into every page — it makes each HTML heavier and throws away the cross-page cache that makes later pages instant. Constraint: premium first, built efficiently; the CSS must stay hashed for the CSP.
- Cheap test (Every fix leaves 1 cheap test, so the same problem never returns):
  - It sits in the cheapest suite that can see the fault, and is seen red on the unfixed code first.
  - It checks the rule the bug broke — every route, item or input that rule covers — and what the user sees: never 1 example, an input, or the code's own constant.
  - Logic that lives in screen code gets a cheap test of that logic, even when a screen test also stays.
  - It owns its clock and its order: no real waits, nothing left from the test before, so it never goes red with nothing wrong.
  - A second fix of the same behaviour first says why the earlier test stayed green, and fixes that test.
  Here: a `tests/dist.test.ts` case that every built HTML page links the same set of stylesheets.
