## Research

- The user's projects: `search-history.sh button height wrap flex stretch action-row min-height btn-lg` — nothing reusable; the hits are other products' own button styles (SoleFocusApp STEP-0043 fixed button widths, not heights across a wrap).
- The web: CSS Flexible Box Layout 1, Editor's Draft 8 May 2026, https://drafts.csswg.org/css-flexbox-1/ ("Calculate the cross size of each flex line") — only a single-line container's line takes the container's cross size; otherwise each line is sized from its own items, so `align-items: stretch` never matches items on different lines. A Stack Overflow question on wrapped buttons of unequal height (kiwix mirror, 2023) was a search hit only, not relied on.
- The model, before searching: give the set one height by value rather than by stretch; risk is depending on stretch; unsure whether another wrapping button group has the same fault.

- Acceptance: both buttons measure 52 px at 320, 393, 744, 1280 and 1920 on all 3 product pages; the privacy link keeps its own type size and padding; the fix uses the existing 52 px height, no new value.
