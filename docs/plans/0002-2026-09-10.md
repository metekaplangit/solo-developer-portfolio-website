## What is coming, and why in this order

Four cards. Two findings are not cards, and the last section says why.

### 1. A dependency the tests import is a dependency the manifest declares

`src/content/products.content.test.ts` imports `parse` from `yaml`. `yaml`
appears in `package.json` only under `overrides`, which pins a version and
installs nothing. It resolves today because Vite (under Astro) and
`@astrojs/language-server` (under `@astrojs/check`) both depend on it and npm
hoists it to the top. Either of those dropping it turns the unit suite red on a
clean install, for a reason nothing in the repository would explain.

Declare it as a devDependency at the version already resolved. First, because
the next card rewrites the lock and this should be in it.

`bump: patch`. Nothing a visitor sees changes.

### 2. The dependency tree is current and agrees with itself

Seven packages behind, proven compatible as a set in a throwaway clone on
2026-09-10 — Headless complete and a Scoped rendered slice, both green, no
guard file rewritten. The set:

The markdown processor renders every product and policy page, so this card
changes what a visitor can see and owes pictures.

`bump: patch`. Nothing a visitor can newly do.

### 3. The preview opens on this project's own port

`.claude/launch.json` names port 4321, which is Astro's default and therefore
whichever project happens to be up. This project's port is 5757 and does not
move. The launch file is what decides where the browser goes, so the port has
to be in three places that agree: the launch file's `port`, its `url`, and the
`preview` script that actually binds.

`bump: patch`. Nothing a visitor sees changes.

### 4. A check reads the page the public receives, not the folder the build wrote

The two findings underneath this one are the same finding twice. Cloudflare Web
Analytics is injecting `static.cloudflareinsights.com/beacon.min.js` into every
live page again, against a non-negotiable in `CLAUDE.md` that forbids analytics
and third-party services. The page's own Content-Security-Policy blocks it, so
nothing is tracking — but the setting is on, and **not one check in this project
would ever have said so**, because every gate reads `dist/` and the injection
happens after `dist/` is served.

So the gap is the real work: nothing here proves what a visitor actually
receives. Build a check that fetches the live URL and holds it against what the
build produced — every script origin, every element the build did not write —
and fails loudly with the origin named.

It cannot join `npm run headless`. That tier is offline, runs on every card, and
must stay fast and deterministic; a network fetch in it would make an unrelated
card red when a CDN hiccups. It is its own command, run by hand and after a
deploy.

`bump: minor` — a check that did not exist is something the project can newly do.
