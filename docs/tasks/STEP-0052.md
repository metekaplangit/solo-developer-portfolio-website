# Task Card — STEP-0052

- **ID:** STEP-0052
- **Type:** feature (UI polish — accessibility, target size)
- **One outcome:** Every pointer target that is not inside a sentence measures at least 24×24 CSS px, and none of them looks any different.
- **Why now:** Measured 2026-07-31 — five separate standalone link groups were 19–21px tall. Third of four polish cards.
- **Prior art:** WCAG 2.2 SC 2.5.8 (AA) requires 24×24 CSS px. Exceptions are Spacing (24px offset to every adjacent target), Equivalent, **Inline** (the target is in a sentence or block of text), User Agent Control and Essential (W3C WCAG 2.2, checked 2026-07-31). Followed: fix the size rather than argue an exception — the Equivalent exception would only move the problem to the nav, and the Spacing exception fails because these links sit ~20px apart.
- **What was under size, measured before the fix:** footer row (Privacy 50×20, Support 55×20, About 41×20, GitHub 48×20); the back/breadcrumb link (119×20); the 404 destinations (5 links at 19px); the supported-products list on `/support/` (21px); the "elsewhere" list on `/about/` (20px).
- **Design decision — one shared rule, not five copies.** All five groups are the same problem with the same fix, and five copies of one treatment is exactly what STEP-0051 had to undo for chips. A single selector list in `global.css` covers `.footer-links a`, `.back a`, `.links a`, `.products a`, `.elsewhere a`. Two per-page copies were written first and then collapsed into it — recorded so the next person does not re-split them.
- **Design decision — height from padding, not from type.** `display: inline-flex` + `min-height: 1.5rem` + `padding-block: var(--space-1)` gives exactly 24px while leaving font size, colour and the persistent underline untouched. Raising the type size would have been a visible change dressed up as an accessibility fix.
- **Avoid:** adding visible chrome to the footer, and touching `Nav.astro` — its links already measure 33px and its narrow-screen one-row-of-four layout is not to be disturbed (review-0001 OPP-01).
- **Non-goals:** the nav; touch-target sizing beyond the AA minimum (the `pointer: coarse` 44px rule in `Nav.astro` stays as it is); STEP-0053.
- **Files:** `src/styles/global.css` (the shared standalone-link rule), `src/components/Footer.astro`, `src/pages/404.astro`.
- **Evidence method:** scripted target-size sweep in a contained browser over all 8 routes × 320/744/1440, classifying every under-size target as inline-exempt or a failure.
- **Proof classification:** machine-verifiable (measured).
- **Required checks:** `npm run build`; `npm run check`; `npm test`; validator; deploy-time Lighthouse a11y gate (≥0.95).
- **Issue links:** Owner UI-polish request, 2026-07-31. Follows STEP-0051; precedes STEP-0053.
- **Rollback/containment:** one global rule plus two files; `git revert -m 1`.
- **Evidence after completion:** **406 targets measured** across 8 routes × 3 widths. **0 failures.** 38 targets remain under 24px and every one is inside a sentence or block of text, so the Inline exception applies — they are prose links in `.prose`, `.policy`, the facts and trust lines, and the maker-note cells (e.g. "Support goes straight to me" followed by "— usually answered in 2–3 business days"). 0 horizontal overflow in the same sweep. Gates: build exit 0, check 0-0-0, 61/61 tests, validator pass.
