# Task Card — STEP-0063

- **ID:** STEP-0063
- **Type:** fix (UI layout — grid completeness)
- **One outcome:** A composed card grid never ends on a short row.
- **Feedback:** `2026-08-01-feature-grid-gap`
- **Why now:** The owner saw "four boxes above, three boxes down" on the Sole Focus page and called it awkward. Measured across six widths, the "What it does" grid held 7 items and was full at exactly one of them: 390px short by 0 (one per row), **768 short by 1, 1024 short by 2, 1280 / 1440 / 1680 short by 1**. The request was explicitly for a site-wide rule, not a one-page fix.
- **Prior art:** None sought. This is arithmetic against a known CSS Grid behaviour that is documented and not in dispute — `auto-fit` resolves the track count from the container's inline size, with no knowledge of the item count. Nothing a search could return would change the answer, and saying so is cheaper than a search that could not.
- **Avoid:** adding one more card and calling it done. Eight items fixes 1-, 2- and 4-column layouts and still leaves 3 columns short by 1 (3 + 3 + 2). The count alone is not a rule; it is this product's current luck.
- **Avoid:** `align-items: start` or any per-cell height fix. The gap is a missing *cell*, not a ragged one, and `.card-grid`'s comment already records that starting cards is what left the policy sections ragged at 127/199/127.
- **Approach:** `evenColumns(count, max)` — the widest column count not exceeding what fits that divides the item count evenly — computed at build time and handed to CSS as `--cols-mid` / `--cols-wide`. Plus the eighth feature the owner asked for.
- **Design decision — two grid classes, not one.** `.card-grid` keeps `auto-fit` and stays correct where cards are a list that happens to wrap and a short last row is invisible. `.grid-even` is for grids where the rectangle IS the composition. Converting every grid on the site would have traded one defect for a worse one: `evenColumns` returns 1 for a prime count, so a five-card list would have become a single column at desktop.
- **Design decision — the eighth feature is not new copy.** DESIGN.md §6 forbids fabricating claims. The added line restates the appearance options already described in the product's own approved "Calm, and always in reach" section — five completion sounds, light and dark themes, accent colors, adjustable sizing.
- **Design decision — the 4-column switch is at 78rem, not at 60.** A quarter track at 78rem is ~263px, which is where `.card-grid`'s own 18rem floor sits. Below that the grid stays at `--cols-mid` rather than cramming four columns of body text into 212px.
- **Acceptance criteria:** (1) Every row full at 390 / 768 / 1024 / 1280 / 1440 / 1680. (2) 0 horizontal overflow at all six. (3) `evenColumns` never returns 0, a fraction, or a value that does not divide the count — it is interpolated straight into `repeat(N, …)`, where a bad value breaks the grid silently. (4) `.card-grid` behaviour unchanged.
- **Non-goals:** converting the home mosaic, the catalog, or the policy grids; changing the card design.
- **Files:** `src/lib/grid.ts` (+ test), `src/styles/global.css` (`.grid-even`, plus the two repairs below), `src/pages/apps/[slug].astro`, `src/content/products/sole-focus.md`, `DESIGN.md`.
- **Evidence method:** headless probe over the built `dist/` at six widths, grouping the grid's children by top edge and comparing the last row against the widest. Exit-code checkable, no screen required.
- **Proof classification:** machine-verifiable (measured row occupancy).
- **Required checks:** `npm run build`; `npm run check`; `npm test`; validator; deploy-time Lighthouse a11y gate (≥0.95).
- **Rollback/containment:** one helper, one class, one content line; `git revert -m 1`.

  **Two defects of my own, caught by re-measuring rather than by reading:**
  1. `.identity > :first-child` (STEP-0061) was meant to nudge the icon. On the site-wide policy, which has no icon, it nudged the text block instead — that page measured 50.4px of page-top against everyone else's 48. A rule from one card silently broke the rule from another. Scoped to `.avatar` / `.avatar-link`.
  2. The back link's `--space-1` block padding — the WCAG 2.2 target-size allowance from STEP-0051 — pushed its text 3px below the page-top line, so the two pages opening with a back link measured 51 against 48. Subtracted in `.page-back`.

  **Known and accepted:** the residual spread is now 47–48px. One pixel, from the line box's own half-leading on an inline-flex link versus a block paragraph. Chasing it would mean shrinking a WCAG target for a difference no one can see.
