# Task Card — STEP-0080

- **ID:** STEP-0080
- **Type:** test (the rendered-geometry gate)
- **One outcome:** `npm run test:ui` reads the built site in a real browser and fails when a rendered-geometry rule in `docs/CHECKLIST.md` is broken, so those rules stop being enforced by whoever remembers them.
- **Feedback:** owner, 2026-08-04 — a UI polish pass, asking that every element be "nicely sized, positioned, aligned … without breaking the user interface".
- **Why now:** seven of the eleven CHECKLIST rules say "read by a person", which means they are enforced when someone remembers to look — and STEP-0078 and STEP-0079 are both defects that survived exactly that. Every card in this batch is proved by this one, and this is what stops the next one from surviving too.
- **What it found on its first run, before anything was fixed:** two failures on a site nobody had reported a problem with — 35 above-the-fold images left to load lazily (STEP-0079), and the `.prose-grid` false positive that made the L1 assertion too broad and had to be narrowed to genuine sets. It also settled a question that would otherwise have been guessed: the small standalone links on this site **pass** SC 2.5.8 through its spacing exception, so the planned "target-size regression" was not one. That is the assertion doing its job in the direction nobody wants — telling you a defect is not there.
- **Prior art:** the mainstream answer to layout regression is the pixel snapshot — Playwright's `toHaveScreenshot()` with committed baselines and `--update-snapshots` to refresh them. (Playwright visual-regression guides, checked 2026-08-04.)
- **Weighed, not adopted:** a pixel baseline would not have caught the defect that motivated this card. A back link losing 6px of invisible padding is a diff of nothing, and a pixel gate fails on every *intended* change, which trains people to re-baseline without looking. This project already asserts facts about built output in `tests/dist.test.ts`, and `docs/CHECKLIST.md` is written as rules rather than as pictures. Facts it is.
- **Avoid:** reaching into `node_modules/puppeteer-core` without declaring it. It is present only transitively — `@lhci/cli → lighthouse → puppeteer-core@24.43.1` — and STEP-0064 exists because packages reachable only as transitive dependencies can stop being reachable with nothing going red. Avoid too: putting this in `npm test`, which would make the sub-second loop wait on a browser.
- **Approach:** `tests/geometry.test.ts` behind its own `vitest.ui.config.ts` and its own `npm run test:ui`. `dist/` is served by a throwaway `node:http` static server inside the suite, so no dev server and no new runtime dependency. Every route is read at 320 / 390 / 768 / 1440 plus one coarse-pointer phone pass, and each CHECKLIST rule that can carry an assertion gets one.
- **Acceptance criteria:** (1) `npm run test:ui` exits 0 on a clean build. (2) Every assertion is seen **red** first against deliberately broken output. (3) `npm test` is unchanged in count and stays under a second. (4) The "what is machine-checked, exactly" table in `docs/CHECKLIST.md` lists every rule this now enforces and nothing it does not. (5) `puppeteer-core` is a declared devDependency.
- **Non-goals:** screenshots, pixel diffs, Lighthouse scores, CI wiring (CI is retired here), and any change to a component or page.
- **Files:** `tests/geometry.test.ts`, `vitest.ui.config.ts`, `package.json`, `docs/CHECKLIST.md`, `docs/TESTING.md`, `docs/SOURCE_MAP.md`, `docs/STATUS.md`, `docs/ROADMAP.md`, `docs/CHECKPOINTS.md`, `docs/CHANGELOG.md`.
- **Evidence method:** exit codes, plus the red-first log for every assertion.
- **Proof classification:** machine-verifiable, exit code.
- **Rollback/containment:** `git revert -m 1`. Additive — no component or page is touched and the existing suites are untouched.
- **Required checks:** `npm run build`; `npm run check`; `npm test`; `npm run test:dist`; `npm run test:ui`; `python3 scripts/validate-governance.py`.
- **Issue links:** none. Owner feedback, 2026-08-04.
- **Evidence after completion:** Gates: build exit 0 (10 pages), check exit 0 with 0/0/0, 111/111 unit, 14/14 dist, **8/8 rendered-geometry in 65s**, validator 44/44.

  **Every assertion was seen red first, against deliberately broken output.**

  | Assertion | Broken with | Result |
  | --- | --- | --- |
  | no page scrolls sideways | a 3000px block on the home page | RED |
  | no text below the size floor | a 10px paragraph on About | RED |
  | targets reach 24px or are exempt | two 10px links touching, on Support | RED |
  | one left rail | the 404 footer padded 40px inboard | RED |
  | a set shares a height on a row | a flex row of two same-class cards, 60px and 120px | RED |
  | no gap wider than the rhythm | 400px above the contact band on Support | RED |
  | nothing on screen loads lazily | the product icon set back to `loading="lazy"` | RED |

  **Two things the red-first pass found that a green run never would.**

  1. **The first three attempts at breaking the layout failed — because the site's own CSP stopped them.** Injecting a `<style>` element into `dist/` does nothing: STEP-0065's policy is `style-src 'self' 'sha256-…'` with no hash for an injected sheet, so the "broken" page rendered perfectly and three assertions looked weak when they were fine. Style *attributes* work, because `style-src-attr 'unsafe-inline'` is the narrow allowance STEP-0065 made for `--hue`. Recorded in `docs/TESTING.md` so the next person does not lose the same twenty minutes.

  2. **The height assertion cannot fail on this site's real markup, and that is worth knowing.** The STEP-0076 defect — two policy cards at 96px and 66px — is now structurally impossible: `.policy-list` is a grid, so it stretches every item in a row to the row's height, and the `.policy-link` inside each item stretches with it. Forcing one card to 400px made *both* 400px. So the assertion was proved on a synthetic flex row instead, and it was also widened while chasing this: it now compares each row at its own level **and one level down**, because the original defect lived in the card inside the grid cell rather than in the cell. It guards a defect class the site does not currently produce — which is what a guard is for.

  **The flake, and what fixed it.** Headless Chrome detaches the navigating frame intermittently here (puppeteer/puppeteer#12294, #13397 — no upstream fix, checked 2026-08-04). Retrying a whole route failed all three attempts on one route, because a route is five page loads and one detach throws away four good readings. Retrying the smallest unit — one page load, with the browser replaced on any failure — took the suite from "fails most runs" to 5 consecutive clean runs at ~65s.
