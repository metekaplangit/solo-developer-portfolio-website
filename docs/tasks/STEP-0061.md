# Task Card — STEP-0061

- **ID:** STEP-0061
- **Type:** fix (UI structure — identity lockup + universal link placement)
- **One outcome:** An app icon sits beside its name on one line, and a back link sits in the same place on every page that has one.
- **Feedback:** `2026-08-01-product-page-header-wasteful`, `2026-08-01-privacy-page-layout-and-link-placement`
- **Why now:** Two owner reports on the same structure. The product page opened with three stacked blocks — back link + icon + chips, then the name and summary well below the icon, then the actions — so the icon and the name it belongs to were separated by two rows. The policy page did the same, and additionally inherited the prose column's `max-width: 43rem; margin-inline: auto` on its back link, which put that link **370.5px** from the viewport edge at 1440 while the product page's identical-purpose link sat at **98.5px**. Same link, two places, depending on the page.
- **Prior art:** NN/G's navigation guidance and the general breadcrumb convention put a "you are here" control top-left, below the header and above the page title, in the *same position on every page* — consistency is the stated point, because readers learn a position rather than search for a control. Checked 2026-08-01 ([NN/G, *Navigation: You Are Here*](https://www.nngroup.com/articles/navigation-you-are-here/); [Pencil & Paper, *Breadcrumbs UX*](https://www.pencilandpaper.io/articles/breadcrumbs-ux)). Followed — it is also exactly what the owner asked for, independently.
- **Avoid:** solving this per page. The owner's ask was explicitly for a rule ("every same category link should be positioned in similar places… universal design choices"), and two pages fixed by hand is what produced the drift in the first place — the policy back link was never *decided* to be centred, it just inherited a column.
- **Approach:** two shared rules in `global.css` — `.page-back` (placement) and `.identity` (lockup) — and both pages reduced to using them with nothing local left.
- **Design decision — this reverses the stacking decision of 2026-07-31, knowingly.** That decision existed for a real reason, recorded at the time: with the avatar in a left column the product's `h1` no longer starts on the shared rail that the nav brand, the footer and every other heading start on. It still does not — the title now starts one icon-width inboard. The owner asked for the lockup explicitly, in their own words, after seeing the stacked version live twice, and the lockup's own left edge **is** on the rail, so the block still reads as aligned to the page. The old reasoning is kept in the `.identity` comment rather than deleted, so a future session does not "discover" it and revert this.
- **Design decision — order, not only geometry.** The chips moved *below* the product name. They were above it, so the first thing read on a product page was "App · Released · macOS" rather than the product's name.
- **Acceptance criteria:** (1) Both back links sit on the shared rail at 390 / 1024 / 1440. (2) The icon is beside the h1, not above it, on both pages. (3) Both header blocks occupy visibly less vertical space. (4) 0 horizontal overflow at all three widths. (5) The site-wide policy, which has no icon, still renders.
- **Non-goals:** paragraph length and wrapping (STEP-0062); the short grid row (STEP-0063); the nav's own layout.
- **Files:** `src/styles/global.css` (`.page-back`, `.identity`), `src/pages/apps/[slug].astro`, `src/pages/privacy/[slug].astro`, `src/components/PolicyArticle.astro`.
- **Evidence method:** headless geometry probe over the built `dist/` at 390 / 1024 / 1440, comparing this branch against `main` built from the same tree. Reports back-link left edge vs the rail, icon-vs-h1 vertical overlap, and header block height. Exit-code checkable, no screen required.
- **Proof classification:** machine-verifiable (measured geometry).
- **Required checks:** `npm run build`; `npm run check`; `npm test`; validator; deploy-time Lighthouse a11y gate (≥0.95).
- **Rollback/containment:** two rules and four call sites; `git revert -m 1`.
- **Issue links:** Feedback items `2026-08-01-product-page-header-wasteful` and `2026-08-01-privacy-page-layout-and-link-placement`. No GitHub issue. Reverses the stacked-head decision recorded on STEP-0042 / 2026-07-31.
