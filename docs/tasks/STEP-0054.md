# Task Card — STEP-0054

- **ID:** STEP-0054
- **Type:** feature (UI polish — motion roles)
- **One outcome:** The site has named motion roles instead of one duration for everything, and the hero entrance fades as well as rises so it reads as an arrival rather than a jolt.
- **Why now:** Owner asked for meaningful motion polish. `--dur: 220ms` was driving a link colour change, a card lift and a button press alike, and `@keyframes rise` animated `transform` only. First of three motion cards (STEP-0054..0056).
- **Acceptance criteria:** (1) Three named roles exist and are used. (2) `rise` animates opacity and transform together. (3) The hero's four children arrive in reading order with real, distinct delays. (4) The `reduce` guard still neutralises everything. (5) 0 horizontal overflow and rail equality unchanged.
- **The roles:** `--dur-fast` **120ms** (a state change you should barely notice — colour on something already present), `--dur` **220ms** (kept, the default: a surface responding to the pointer), `--dur-slow` **420ms** (an entrance — something arriving that was not there). `--ease` unchanged; `--ease-out` `cubic-bezier(0.16, 1, 0.3, 1)` added, because an entrance should land rather than drift to a stop.
- **Design decision — the default did not move.** Every existing hover keeps 220ms. The point is that entrances are a different job, not that everything should be slower; changing the default would have altered every surface on the site under cover of a token rename.
- **Prior art:** nothing external needed. The roles follow the project's own pattern — `--space-*`, `--band-y-*`, `--display-*` were each introduced for exactly this reason, and each had a card that found real drift first.
- **Two real defects found while doing it, both fixed here:**
  1. **The hero stagger had never run.** The delays were written as `.band-hero h1` and lost on specificity to `.band-hero > .rail > *` — three classes beat two — so every child computed a **0s** delay and all four arrived together. Measured before the fix: `P.over 0s, H1 0s, P.lede 0s, DIV.actions 0s`. Selecting through the same path (`.band-hero > .rail > h1`) makes them equal and later-wins does the rest.
  2. **`astro check` had been failing since v0.44.4.** STEP-0053's last edit put a JSX comment *inside* an `<Image>` attribute list in `ScreenshotShowcase.astro`, which the bundler tolerated and the type-checker did not — and `npm run check` was not re-run after that edit, so it shipped. Two `ts(1005)`/`ts(1002)` errors. The comment moved above the element. **Recorded because it is a process failure, not just a typo: the check exists precisely to catch this and it was skipped.**
- **Avoid:** lengthening existing hover transitions, and introducing a fourth duration.
- **Non-goals:** the reveal and the nav scroll state (STEP-0055); page transitions (STEP-0056).
- **Files:** `src/styles/global.css` (roles, link transition), `src/components/Nav.astro`, `src/components/Footer.astro`, `src/pages/index.astro` (`rise` + stagger), `src/components/ScreenshotShowcase.astro` (the check regression).
- **Evidence method:** computed `transition-duration` per role; computed `animation-delay`/`animation-duration` for all four hero children; the `rise` keyframes read back off the running animation via `getAnimations()`.
- **Proof classification:** machine-verifiable (measured).
- **Required checks:** `npm run build`; `npm run check`; `npm test`; validator; deploy-time Lighthouse a11y gate (≥0.95).
- **Issue links:** Owner motion-polish request, 2026-07-31. Precedes STEP-0055.
- **Rollback/containment:** token-level plus one keyframe; `git revert -m 1`.
- **Evidence after completion:** Roles resolve `--dur-fast .12s`, `--dur .22s`, `--dur-slow .42s`, `--ease-out cubic-bezier(.16, 1, .3, 1)`. A nav link measures `0.12s`; a button still measures `0.22s` across all five of its properties. Hero children now measure delays **0s / 0.06s / 0.12s / 0.18s** at `0.42s` each — the whole entrance lands in 0.6s — where all four measured 0s before. The `rise` animation read back off the element reports keyframes `{offset 0, opacity 0, translateY(12px)} → {offset 1, opacity 1, translateY(0px)}`, so the fade is real and not merely declared. `astro check` back to **0 errors / 0 warnings / 0 hints** (was 2 errors).
