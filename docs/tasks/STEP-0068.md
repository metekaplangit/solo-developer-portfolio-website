# Task Card — STEP-0068

- **ID:** STEP-0068
- **Type:** test (coverage)
- **One outcome:** A suite that fails when the built pages are wrong, not only when a pure function is.
- **Feedback:** AUDIT-0010. Tests scored 72 — the lowest area not deliberately unstaffed.
- **Why now:** 721 test lines against 4308 source lines, and the split was not even: every pure module in `src/lib` was tested while **14 components and 8 pages had no test at all**. The only things between a broken page and production were `astro build`, `astro check` and the deploy-time Lighthouse gate. None of them notices a wrong canonical URL, malformed JSON-LD, a third-party script, a missing CSP, or the wrapping rule silently not reaching rendered Markdown — and that last one is not hypothetical: STEP-0064 exists because the packages applying that rule were reachable only as transitive dependencies of astro. It could have stopped working without one test going red.
- **Prior art:** passing unit tests do not evidence structural correctness; tests check behaviour, not the artifact ([Sonar, code quality 2026](https://www.sonarsource.com/resources/library/code-quality-2026/), read 2026-08-01). The gap here is exactly between "the function is right" and "the page is right".
- **Avoid:** a component-rendering harness (Astro's container API or similar). It proves a component in isolation, not the page a visitor gets, and it adds a dev dependency to a project holding two runtime deps on purpose. `dist` is already built by every gate — assert against it.
- **Avoid:** folding this into `npm test`. That suite runs in under a second and is run constantly; making it wait on a build is how a fast suite stops being run.
- **Approach:** a vitest suite under `tests/` that reads `dist/**/*.html` directly, with its own config and its own script.
- **Design decision — a second config file, not a `--include` flag.** vitest 4 has no `--include` CLI option (it errors `Unknown option`), and a second config states the separation where someone will actually see it.
- **Design decision — assert the route list explicitly.** A suite that loops over whatever it finds passes happily when the build emits nothing; the route list and a non-zero JSON-LD block count are what stop a silent no-op from reading as green.
- **Acceptance criteria:** (1) Fails on a wrong canonical URL. (2) Fails on malformed JSON-LD. (3) Fails when the wrapping rule is absent from rendered Markdown. (4) Adds no runtime dependency. (5) `npm test` stays under a second.
- **Non-goals:** component unit tests; visual regression; replacing the Lighthouse gate.
- **Files:** `tests/dist.test.ts` (new), `vitest.dist.config.ts` (new), `vitest.config.ts`, `package.json`, `docs/TESTING.md`.
- **Evidence method:** each assertion run against deliberately broken build output and seen red, then seen green again after a rebuild. Exit codes throughout, no screen.
- **Proof classification:** machine-verifiable.
- **Required checks:** `npm run build`; `npm run check`; `npm test`; `npm run test:dist`; `python3 scripts/validate-governance.py`.
- **Rollback/containment:** additive; `git revert -m 1`.
- **Issue links:** AUDIT-0010. No GitHub issue.
- **Evidence after completion:** 8 build-output tests, all passing. `npm test` unchanged at 96/96 in **0.90 s** — the new suite is excluded, and the fast loop stayed fast. Gates: build exit 0, check 0/0/0, 96/96 unit tests, 8/8 dist tests, validator 44 checks passed. No dependency added.

  **Every assertion was seen red before it was trusted.** A test never seen to fail is not a test, so each was run against deliberately broken output and then against a clean rebuild:

  | Break introduced | Suite exit | Tests failed |
  |---|---|---|
  | Canonical rewritten to `http://localhost:4321/about/` | 1 | 2 |
  | `{oops,` spliced into a JSON-LD block | 1 | 1 |
  | CSP meta element stripped from `/support/` | 1 | 1 |
  | `cloudflareinsights.com/beacon.min.js` injected into `/` | 1 | 1 |
  | Every non-breaking space replaced with a plain space | 1 | 1 |
  | `dist/404.html` deleted | 1 | 1 |
  | *(none — clean rebuild)* | **0** | 0 |

  The localhost break tripping two assertions rather than one is correct: it violates both the exact-canonical rule and the no-dev-host rule.

  **A dead end worth one line:** `vitest run --include 'tests/**'` fails with `CACError: Unknown option --include` on vitest 4. The remedy is a second config file, which reads better anyway.
