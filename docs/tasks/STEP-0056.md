# Task Card — STEP-0056

- **ID:** STEP-0056
- **Type:** feature (UI polish — cross-document view transitions)
- **One outcome:** Moving between pages becomes a transition rather than a hard cut, with **no JavaScript added**.
- **Why now:** it was the last hard edge on the site and the only one a visitor met on every single click. Third and last motion card.
- **Prior art:** `@view-transition { navigation: auto; }` is the native CSS at-rule for same-origin, cross-document navigation — Chrome 126+, Safari 18.2+, Firefox in progress; **both** the outgoing and incoming page must opt in, which is automatic here because `global.css` is on all eight routes (MDN, *@view-transition*; Chrome for Developers, *Cross-document view transitions for multi-page applications*; checked 2026-07-31). Followed.
- **Avoid — and this is the main decision on the card:** Astro's `ClientRouter`. It converts a static multi-page site into a single-page app, which means every script must be re-initialised on each navigation — the gallery's `initGallery` included — and it contradicts `docs/ARCHITECTURE.md`'s guardrail that nothing runs in production. The CSS at-rule delivers the same visible result for **zero bytes of script**. Also avoided: leaving persistent chrome unnamed, which is the most common way this feature looks broken — without its own `view-transition-name` the sticky header is captured inside the root snapshot and visibly cross-fades against itself on every navigation.
- **Acceptance criteria:** (1) The at-rule reaches all eight routes. (2) Header and footer carry their own transition names. (3) No JavaScript added. (4) Transitions do not run under `prefers-reduced-motion: reduce`. (5) Navigation still works normally where unsupported. (6) 0 horizontal overflow, rail equality unchanged.
- **Design decision — no transition at all under `reduce`, not a fast one.** `DESIGN.md` §6 asks for an *alternative*, not a shortened version of the same effect, so the pseudo-elements get `animation: none !important` rather than a clipped duration.
- **Design decision — the shared-element morph is deliberately NOT shipped in this card.** The plan proposed giving the product screenshot a matched `view-transition-name` so it morphs from the home band into the product page. Its entire value is how it looks, and scroll- and transition-time appearance cannot be observed in the harness available on this machine — the same limitation that removed the nav "settle" in STEP-0055. Shipping an effect whose only merit is visual, unseen, would be the thing this project keeps refusing to do. The plain cross-fade ships now; the morph is a follow-up worth taking **once the cross-fade has been watched on the live site** and the mechanism is known to behave.
- **Non-goals:** per-route bespoke transitions; animating the nav's current-page pill across routes; the morph (above).
- **Files:** `src/styles/global.css` (`@view-transition`, root group timing, the `reduce` override), `src/components/Nav.astro`, `src/components/Footer.astro`.
- **Evidence method:** per-route inspection of the built HTML and its linked CSS for the at-rule; computed `view-transition-name` on the header at every route and width; a diff check that no script was added.
- **Proof classification:** machine-verifiable (structural), with appearance recorded **unproven** below.
- **Required checks:** `npm run build`; `npm run check`; `npm test`; validator; deploy-time Lighthouse a11y gate (≥0.95).
- **Unproven, stated rather than rounded up:** what the transition *looks like*. The harness here cannot observe a navigation mid-transition. What is proved is that the mechanism is correctly and completely wired. **Watch it on the live site after deploy**, the way the gallery counter was in STEP-0051 — and if it reads badly, one at-rule is the whole rollback.
- **Issue links:** Owner motion-polish request, 2026-07-31. Follows STEP-0055; closes the motion phase (STEP-0054..0056).
- **Rollback/containment:** one at-rule plus two `view-transition-name` declarations; `git revert -m 1` returns to hard cuts.
- **Evidence after completion:** The at-rule is present in the linked CSS of **all eight routes** (`/`, `/apps/`, `/apps/sole-focus/`, `/privacy/`, `/privacy/sole-focus/`, `/support/`, `/about/`, `/404`), so both ends of every navigation opt in. The header computes `view-transition-name: site-header` at **21 page-states** (7 routes × 320/744/1440); the footer carries `site-footer`. The whole change is **42 added lines across 3 files, all CSS** — the only diff line matching a script pattern is the comment explaining why `ClientRouter` was not used.
