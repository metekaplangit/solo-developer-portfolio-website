# Task Card — STEP-0071

- **ID:** STEP-0071
- **Type:** fix (a policy lead with more than one paragraph)
- **One outcome:** The opening paragraphs of a privacy policy read as paragraphs, so the first thing a store reviewer sees on `/privacy/magic-notes/` is not a single grey block.
- **Feedback:** Owner instruction, 2026-08-03: add the app icon to the Magic Notes privacy page as Sole Focus has, then look for inconsistencies between the pages and fix them.
- **Why now:** the Magic Notes app is being submitted, and its shipped build hard-codes `https://metkapstudio.com/privacy/magic-notes/`. The defect sits in the first thing rendered on that page, above every section, so a store reviewer following that link reads it before anything else. It also cannot be corrected in the app afterwards, which makes the page the only place to fix it.
- **What the icon turned out to be:** already there. `PolicyArticle` renders `ProductAvatar` from the product's own `icon`, so adding the icon in STEP-0070 put it on the policy page in the same pass. Both pages emit identical markup — `<img class="avatar avatar-lg" src="/media/<slug>/icon.svg" width="56" height="56">`. Nothing to do, and nothing was changed for it.
- **What the comparison actually found:** `PolicyArticle.astro:278` set `margin: 0` on every `<p>` inside `.policy-lead`. Correct for a one-paragraph lead, which is all this site had until STEP-0070 gave Magic Notes a three-paragraph one; those three then ran together into one block of text with no separation. Sole Focus never showed it because its lead is a single sentence.
- **What the comparison found consistent** (checked, unchanged, recorded so it is not re-checked): both policies emit the same 10 sections and the same 3 chips in the same order; both carry the same frontmatter field set; both products differ only by `price`, `makerNote` and `releaseDate`, each deliberately absent for an unreleased product; both product pages emit `SoftwareApplication` + `BreadcrumbList` differing only by `offers`; the JSON-LD `image` on each resolves to that product's own icon; all four pages carry the same Open Graph and Twitter card shape.
- **Approach:** one CSS rule. `p + p` only, so the single-paragraph case renders byte-for-byte as before and the block still sits flush against the chips above and the sections below. No component structure, no content, no schema.
- **Avoid:** giving `.policy-lead p` a blanket margin. That would add space above the first paragraph and below the last, moving both edges of a block whose position on every existing page is deliberate.
- **Acceptance criteria:** (1) the three Magic Notes lead paragraphs render separated. (2) The Sole Focus lead is unchanged — `p + p` cannot match a lone paragraph. (3) No content file changes.
- **Non-goals:** the doubled wording in both policies' `og:description` ("Privacy policy — <name> Privacy Policy"), which is identical on both pages and therefore not an inconsistency; the Magic Notes store link, price and release date, which stay absent until Apple accepts the app.
- **Files:** `src/components/PolicyArticle.astro`, `docs/STATUS.md`, `docs/ROADMAP.md`, `docs/CHECKPOINTS.md`, `docs/CHANGELOG.md`.
- **Evidence method:** the built page rendered in a headless browser and read, before and after.
- **Proof classification:** machine-verifiable, plus a rendered comparison.
- **Required checks:** `npm run build`; `npm run check`; `npm test`; `npm run test:dist`; `python3 scripts/validate-governance.py`.
- **Rollback/containment:** `git revert -m 1`. One CSS rule; reverting restores the previous spacing and touches nothing else.
- **Issue links:** none. Owner instruction, 2026-08-03.
- **Evidence after completion:** Gates: build exit 0 (10 pages), check exit 0 with 0/0/0, 104/104 unit tests, 10/10 dist tests, validator 44/44.
