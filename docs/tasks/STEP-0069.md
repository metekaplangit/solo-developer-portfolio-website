# Task Card — STEP-0069

- **ID:** STEP-0069
- **Type:** content (a second product enters the catalogue)
- **One outcome:** Magic Notes has a live product page and its own privacy page, so the URLs the app's store submission needs resolve before the app ships.
- **Feedback:** Owner instruction, 2026-08-02. The app is finished but unreleased; its submission sheet needs a privacy URL that returns a real page, and the app itself needs a marketing link to point at.
- **Why now:** The Magic Notes submission sheet (`store-assets/listings/listings-2026-08-01-1430-first-launch-pack/SUBMISSION_SHEET.md` in that project) records `https://metkapstudio.com/privacy/magic-notes/` as **needs-user-input** — the URL is already written into the submission draft and currently 404s. Apple 5.1.1(i) requires that URL to serve a policy at review time, and a link inside the shipped app cannot be changed after the build. Publishing the two pages now removes the last site-side blocker; the trademark search and the price remain the owner's, and neither depends on this.
- **Prior art:** none sought. The site already routes `/apps/[slug]/` and `/privacy/[slug]/` from content collections, so this is the project's own established pattern applied a second time. No external source knows this schema.
- **Avoid:** inventing copy. Every claim on both pages traces to the Magic Notes project — its `README.md` product boundary, `docs/SECURITY.md` privacy controls, and the fact-checked copy pack the owner already approved on 2026-08-01. Nothing on these pages is new marketing written here.
- **Avoid:** a `makerNote`. The schema requires the maker's explicit approval of that exact copy (STEP-0035), and it has not been given for this product.
- **Avoid:** a price, a store link, a release date, or a screenshot. None is verified: the app has no purchase code anywhere in its source, no store listing exists, and no screenshots have been produced. An unverified value here would ship a false claim and a broken `offers` JSON-LD.
- **Approach:** two Markdown files and nothing else — `src/content/products/magic-notes.md` and `src/content/policies/magic-notes.md`. No component, page, style, or schema change is needed; `status: in-development` with an empty `storeLinks` already renders "Not yet available — check back soon", and `ProductAvatar` already draws a monogram when a product has no icon.
- **Design decision — the hue is `#B2BBC5`, read from the app.** The Magic Notes icon is deliberately achromatic (`#4F5963` frame on near-white), and the app's own accent palette names that family Graphite. `#B2BBC5` is the exact value the app renders Graphite as in dark appearance (`NotebookVisualSystem.swift:307`), which is the appearance this site's stage matches. DESIGN.md §2 wants the product to colour its band rather than the site to pick for it, and the app's first-run default accent — a burnt orange, `#FF9565` — was rejected because it is within two points of Sole Focus's `#ff9245` and the catalogue would read as one product twice.
- **Design decision — `reviewStatus: draft`.** The policy is truthful to `docs/SECURITY.md` today, but it has not been read against the shipped build by a human. Draft is the honest state and the schema's own default; it does not weaken the page or hide it.
- **Design decision — the page goes public on `/apps/`.** The catalogue lists every product regardless of status, and Apple follows the marketing URL. A page reachable only by direct link would be a page the reviewer cannot find. It carries the "In development" badge, which is true.
- **Acceptance criteria:** (1) `/apps/magic-notes/` and `/privacy/magic-notes/` both build and render. (2) The privacy URL matches the submission sheet character for character. (3) No price, store link, release date, or screenshot is claimed. (4) The dist route assertion counts the two new routes. (5) A content test pins the release state and the privacy URL so a later edit cannot silently break the submitted link.
- **Non-goals:** the app icon and screenshots (the owner supplies those later); the Magic Notes home-page band; any change to Sole Focus; the trademark, price, and category decisions, which are the owner's alone.
- **Files:** `src/content/products/magic-notes.md` (new), `src/content/policies/magic-notes.md` (new), `src/content/products.content.test.ts`, `tests/dist.test.ts`, `docs/STATUS.md`, `docs/ROADMAP.md`, `docs/CHECKPOINTS.md`, `docs/CHANGELOG.md`.
- **Evidence method:** full build, then the built `dist/` read directly — both new routes present, the canonical URLs correct, the privacy URL identical to the submission sheet's, and no `offers` block emitted for an unreleased product.
- **Proof classification:** machine-verifiable.
- **Required checks:** `npm run build`; `npm run check`; `npm test`; `npm run test:dist`; `python3 scripts/validate-governance.py`.
- **Rollback/containment:** `git revert -m 1`. Both files are additive content; reverting removes two routes and touches no existing page.
- **Issue links:** none. Owner instruction, 2026-08-02.
- **Evidence after completion:** Gates: build exit 0 (**10 pages**, was 8), check exit 0 with 0 errors / 0 warnings / 0 hints, **102/102** unit tests (96 before; 6 added), **10/10** dist tests (8 before; 2 added), validator 44/45 — the one failure was `sync.product_tag_matches_git` before the tag existed, and it passes after.

  **Both new dist assertions were seen red first.** The built output was broken deliberately — the privacy canonical rewritten to `/privacy/magicnotes/` and an `"offers"` key injected into the product page's JSON-LD — and `npm run test:dist` exited 1 with 4 failures: the two new assertions plus the two existing ones (canonical match, JSON-LD validity) that catch the same damage. A rebuild returned all 10 to green.

  **Versionable, not internal.** The entry was first written as internal work. `VERSION_CONTROL.md` puts generated route URLs inside the public contract, and this adds two — so it ships as **v0.46.0** with a changelog entry, rather than following STEP-0064..0068's untagged pattern.

  **The hue clears contrast by measurement, not by eye.** `#B2BBC5` is rendered as *text* by `.chip-accent`, whose colour is `--accent-hover` (the hue) on a 16% tint of itself. Against the near-black stage that computes to **7.9:1**, well clear of the 4.5:1 the deploy-time Lighthouse a11y gate enforces. The app's first-run accent `#FF9565` would also have passed contrast; it was rejected for being 2 points from Sole Focus's `#ff9245`, which is a catalogue problem rather than an accessibility one.

  **What the pages deliberately do not say.** No price, no store link, no release date, no screenshot, no icon, no maker's note. Each is either unverified or unapproved, and `docs/SECURITY.md` in the Magic Notes project is the source for every privacy claim made. The four owner-only decisions — trademark, price, category, and the icon and screenshots — are untouched and unblocked by this.
