# Task Card — STEP-0060

- **ID:** STEP-0060
- **Type:** fix (UI rhythm — page-top distance)
- **One outcome:** Every page starts the same distance below the header, and that distance is half what it was.
- **Feedback:** `2026-08-01-hero-empty-space`, `2026-08-01-apps-page-top-space`
- **Why now:** Two owner reports, both about arriving on a page and reading nothing. Measured before the fix, the gap from the header's bottom edge to the first ink was **170px on home, 96px on apps / about / support / privacy-index / 404, 49px on a policy page and 32px on a product page** — four different answers to one question, on a seven-page site. The owner asked for the apps gap to be cut "at least half" and for every page to match.
- **Prior art:** None sought and none needed. This is the site's own token system deciding one number; there is no framework behaviour, platform convention or external API involved. Recording the absence rather than padding the card with a search that could not have changed the answer.
- **Avoid:** deleting `--band-y-lg`. It is still correct for a band further down a page that opens a new movement (`.band-loose` neighbours, the policy tail). What was wrong was using the *largest* band value as the *page-top* value; the token is fine, the application was not.
- **Avoid:** keeping `min-height` on the hero and merely reducing the padding. With `align-items: center` the min-height inserts its slack **above and below equally**, so shrinking the padding moves the content up and grows the void underneath by the same amount. Both of the owner's red boxes came from that one declaration.
- **Approach:** one new token, `--page-top: clamp(2rem, 4vw, 3rem)` — half of `--band-y-lg` by construction — applied to the first band of every route, and the hero's `min-height` / vertical centring deleted so its height is its content.
- **Design decision — one token, not a per-page value.** The owner's second ask ("all of my pages have similar same size emptiness matching each other") is not satisfiable by editing six paddings to the same number; the next page added would get a seventh. `--page-top` is the rule, and `.band-lead` carries it for every page that uses the band system.
- **Acceptance criteria:** (1) All 8 routes measure an identical header-to-first-ink gap. (2) That gap is ≤ half the previous 96px on the Apps page. (3) The home hero's height falls, with the space below the buttons reduced. (4) 0 horizontal overflow at 390 / 1024 / 1440. (5) `--band-y-lg` still exists and is unchanged.
- **Non-goals:** the centred policy back link and the icon-beside-headline grouping (STEP-0061); paragraph length and wrapping (STEP-0062); the short grid row (STEP-0063).
- **Files:** `src/styles/global.css` (`--page-top`, `.band-lead`), `src/pages/index.astro`, `src/pages/apps/index.astro`, `src/pages/apps/[slug].astro`, `src/pages/privacy/[slug].astro`, `src/components/PolicyArticle.astro`.
- **Evidence method:** headless geometry probe over the built `dist/` at 1440 (and 390/1024 for the hero), reporting header-bottom → first-ink per route. Exit-code checkable, no screen required. Probe lives outside the repo, in the owner's scratch space.
- **Proof classification:** machine-verifiable (measured geometry).
- **Required checks:** `npm run build`; `npm run check`; `npm test`; validator; deploy-time Lighthouse a11y gate (≥0.95).
- **Rollback/containment:** one token plus six call sites; `git revert -m 1`.
- **Issue links:** Feedback items `2026-08-01-hero-empty-space` and `2026-08-01-apps-page-top-space`. No GitHub issue. Followed by STEP-0061..0063, which drain the rest of the same feedback pass.
- **Evidence after completion:**

  | home | 170 | 48 |
  | apps | 96 | 48 |
  | product | 32 | 48 |
  | privacy-index | 96 | 48 |

  One distinct value across all eight routes, down from four. Apps exactly halved. Hero band 738px → 542px at 1440; the space between the buttons and the next band went 146px → 72px. Horizontal overflow 0 at 390 / 1024 / 1440. Gates: build exit 0, check 0/0/0, 61/61 tests.
