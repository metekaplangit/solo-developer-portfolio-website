# Task Card — STEP-0078

- **ID:** STEP-0078
- **Type:** fix (a shared rule that stopped reaching two routes)
- **One outcome:** The shared standalone-link rule reaches every standalone link again, so the back links and the "More apps" row carry the target height and the page spacing the rest of the site has.
- **Feedback:** owner, 2026-08-04 — a UI polish pass over sizing, spacing and placement.
- **Why now:** it is a rule that was shipped, measured, and then quietly stopped applying. Nothing reported it because nothing could.
- **What it actually was:** `global.css` grants a 24px minimum height to `.footer-links a, .back a, .links a, .products a, .elsewhere a` (STEP-0052). No markup in `src/` has used `.back` since the back link was renamed `.page-back` — the selector matched nothing, on any page. Two consequences, both measured at 1440px before the change:
  - the back links rendered **18px** tall on `/apps/sole-focus/`, `/apps/magic-notes/` and `/privacy/sole-focus/`, against the 24px the rule intends;
  - `.page-back` had been written to SUBTRACT `--space-1` from its `padding-top` *because* the link carries that padding — and it no longer did, so those three routes measured **47px** from the header to the first ink box against **48px** on the other six. A 1px inconsistency in the one distance STEP-0060 exists to keep identical.

  Separately, the "More apps" row at the foot of a product page is a bare `<ul>` with no class at all, so it was the one standalone link row on the site outside the shared rule: **91.1×18** and **79.5×18** on a phone.
- **Prior art:** WCAG 2.2 SC 2.5.8 asks for 24×24 CSS px, with an exception where a 24px circle centred on each undersized target does not intersect another target. ([W3C, Understanding SC 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html), checked 2026-08-04.)
- **Weighed, not adopted:** measured against that exception, these links **passed** — they sit alone, so the spacing exception covers them. This card is therefore **not** an accessibility fix and must not be recorded as one. It is a shared rule that lost its surface, and the visible cost is the 1px page-top difference and a target smaller than this site's own standard.
- **Avoid:** adding a second copy of the padding rule beside `.page-back`. Five copies of one treatment is what STEP-0051 had to undo for chips and what STEP-0052 explicitly refused. Avoid too: buying the height with a larger font — the target grows, the design does not.
- **Approach:** three small edits, all pointing existing rules at the class that exists. `.back a` becomes `.page-back a` in the target-size rule and in the two in-content underline rules; the "More apps" list takes the shared `links` class the 404 destinations already use. `.page-back`'s `padding-top` subtraction is left exactly as it is — it becomes correct again the moment the padding it assumes is granted.
- **Acceptance criteria:** (1) no standalone link on any of the 9 routes measures under 24px in either axis on a phone. (2) The back-link routes measure the same header-to-ink distance as every other route. (3) No type size, colour or underline treatment changes. (4) `.back` appears nowhere in the stylesheet.
- **Non-goals:** the 44px coarse-pointer guidance (nav and gallery dots already exceed it, and 24px is this site's stated standard); links inline in a sentence, which the exception covers; and the gate that would have caught this, which is STEP-0080.
- **Files:** `src/styles/global.css`, `src/pages/apps/[slug].astro`, `docs/STATUS.md`, `docs/ROADMAP.md`, `docs/CHECKPOINTS.md`, `docs/CHANGELOG.md`.
- **Evidence method:** the built pages read in a headless browser at 1440px and at 390px with a coarse pointer, before and after: link box heights, and the header-to-ink distance measured with a Range over the text node rather than the box around it.
- **Proof classification:** machine-verifiable measurement.
- **Rollback/containment:** `git revert -m 1`. One selector list and one class attribute.
- **Required checks:** `npm run build`; `npm run check`; `npm test`; `npm run test:dist`; `python3 scripts/validate-governance.py`.
- **Issue links:** none. Owner feedback, 2026-08-04.
- **Evidence after completion:** Gates: build exit 0 (10 pages), check exit 0 with 0 errors / 0 warnings / 0 hints, 111/111 unit, 14/14 dist, validator 44/44.

  **Read from the rendered DOM.** Before, at 1440px: `/apps/sole-focus/`, `/apps/magic-notes/` and `/privacy/sole-focus/` measured **47px** from the header's bottom edge to the first ink box, against **48px** on the other six routes; their back links measured **18px** tall. On a phone with a coarse pointer, **6** standalone links measured under 24px — the three back links and the "More apps" rows.

  After: back links **32.8px**, the same three routes measure the page-top the other six do, and **0** standalone links under 24px on any of the 9 routes. The header-to-ink figure is measured with a `Range` over the text node rather than the element box, because `.page-back` deliberately puts its tap-target padding *above* the text — a box measurement reads that intentional 4px as drift.

  **A claim this card removed rather than made.** The plan proposed this as an accessibility regression against SC 2.5.8. It is not one: the gate applies the criterion's spacing exception, and every one of those links clears it — they sit alone, with no other target inside a 24px circle. The defect is real and the fix stands, but it is a shared rule losing its surface, not a WCAG failure, and recording it as the latter would have been a false claim in the changelog.
