# Task Card — STEP-0050

- **ID:** STEP-0050
- **Type:** feature (UI polish — token conformance)
- **One outcome:** No page invents a spacing step or a type size. Band rhythm comes from the `--band-y-*` tokens that already existed, and the page lede is one role at one size.
- **Why now:** Owner asked for a UI polish pass. Measured 2026-07-31 at 1440: the banded routes hand-rolled **six different `clamp()` padding expressions**, rendering **96 / 80 / 80 / 80 / 48px** on the home page — and **80px is a step that exists nowhere in the system** — while `--band-y-tight` / `--band-y` / `--band-y-loose` / `--band-y-lg` sat defined in `global.css` and referenced by no banded page. First of four polish cards (STEP-0050..0053).
- **Acceptance criteria:** (1) No band uses a literal `clamp()` for its vertical padding; every band gap resolves to a rhythm token. (2) One lede size, used by both the home page and the catalog. (3) `MakerNote`'s raw `1.05rem` is a scale value. (4) Before/after rendered values recorded below. (5) 0 horizontal overflow and rail equality unchanged across the width matrix.
- **Mapping — snap to the nearest existing step, add none:** hero top `96 → --band-y-lg` (96, unchanged); the four 80px band gaps `→ --band-y` (72, −8px); the maker tail `48 → --band-y-tight` (40, −8px); the catalog masthead `88 → --band-y-lg` (96, +8px) and its lower `48 → --band-y-tight` (40, −8px). Every move is ≤8px, so no new named step was needed — the plan allowed adding one if a mapping had moved a gap by more than ~16px, and none did.
- **Design decision — one lede role, not two.** The home and catalog ledes differed only in their cap (`1.3125rem` vs `1.25rem`), one pixel apart. That is drift, not a decision, so both now use a new `--text-lede`. The hero's lede loses 1px at the cap.
- **Prior art:** none needed externally — the project's own STEP-0038 band-rhythm note already states that rhythm comes from contrast between *named* steps, never from per-page values, and STEP-0042 fixed the same class of problem for cards. Followed.
- **Avoid:** re-deriving a new rhythm. This card moves values onto the existing scale; it does not design one.
- **Non-goals:** the shared chip (STEP-0051); target sizes (STEP-0052); image loading (STEP-0053); any change to the display ramp itself.
- **Files:** `src/styles/global.css` (`--text-lede`), `src/pages/index.astro` (5 band paddings + lede), `src/pages/apps/index.astro` (2 + lede), `src/components/ProductBand.astro` (1), `src/components/MakerNote.astro` (body size).
- **Evidence method:** computed `padding-top`/`padding-bottom` for every top-level band on the banded routes, asserted to be a member of the rhythm token set resolved at that width; plus the overflow and rail sweep.
- **Proof classification:** machine-verifiable (measured).
- **Required checks:** `npm run build`; `npm run check`; `npm test`; validator; deploy-time Lighthouse a11y gate (≥0.95).
- **Issue links:** Owner UI-polish request, 2026-07-31. Precedes STEP-0051.
- **Rollback/containment:** value-only changes in five files; `git revert -m 1`.
- **Evidence after completion:** Band conformance — every top-level band padding on `/` and `/apps/` is a member of the rhythm set at **both** measured widths: `{40, 72, 96, 120}` at 1440 and `{32, 48, 64, 80}` at 744. **0 off-scale values.** Home page before → after at 1440: `96 / 80 / 80 / 80 / 48` → `96 / 72 / 72 / 72 / 40`. Lede is now a single size on both pages (20px at 1440, 17px at 744; was 21px vs 20px). Sweep — **56 page-states** (8 routes × 7 widths), 0 horizontal overflow, rail equality intact. Gates: build exit 0, check 0-0-0, 61/61 tests, validator pass.
