# Task Card — STEP-0072

- **ID:** STEP-0072
- **Type:** feature (the page checklist)
- **One outcome:** The site has one written checklist of the rules a page must satisfy, so the owner can point at a rule instead of reporting the same class of defect a fourth time.
- **Feedback:** `2026-08-03-text-cut-in-the-middle-checklist` (asks for the mechanism), `2026-08-03-privacy-policy-cards-no-harmony` (asks that it cover layout), `2026-08-03-product-page-empty-space` (asks that it cover whitespace).
- **Why now:** three reports in one sitting, each ending with the same instruction — write this down so it stops coming back. Nothing else in the batch can be checked against a rule until the rules exist.
- **The owner's decision, taken at planning:** a document **and** an automated check, not one or the other. This card is the document; STEP-0073 is the enforcement, because a check landing before the site passes it would put a deliberately red suite on `main`.
- **Prior art:** `text-wrap: pretty` cannot be the mechanism. WebKit evaluates a whole paragraph, but Chromium — the engine the owner reads the site in — adjusts only the **last four lines**, so a break in the middle of a long paragraph is out of its reach entirely. The remedy is the typographer's one, a non-breaking space binding the pair. Source: [WebKit, *Better typography with text-wrap pretty*](https://webkit.org/blog/16547/better-typography-with-text-wrap-pretty/).
- **Avoid:** writing rules nobody can act on. "Balanced whitespace" as a bare phrase is a mood, not a rule; each entry names the failure it catches and says plainly whether a machine or a person checks it. Also avoided: describing a rule as enforced when nothing enforces it — the one failure that makes a checklist worse than none.
- **Approach:** one document, `docs/CHECKLIST.md`, in three groups — Text, Layout, Whitespace — each opening with the owner's own words for that group. Every rule carries its failure mode and its checker. A table at the end lists exactly which rules are machine-checked and by which suite. No code, no component, no content change.
- **Acceptance criteria:** (1) the document exists and covers text, layout and whitespace, each quoting the owner. (2) Every rule says whether it is machine-checked or read by a person. (3) The claim about which rules are enforced matches what the suites actually assert today. (4) No source file changes.
- **Non-goals:** applying the rules (STEP-0073), the automated assertions themselves (STEP-0073), and the three visual defects the reports also named (STEP-0074..0076).
- **Files:** `docs/CHECKLIST.md`, `docs/STATUS.md`, `docs/ROADMAP.md`, `docs/CHECKPOINTS.md`, `docs/CHANGELOG.md`, `docs/SOURCE_MAP.md`.
- **Evidence method:** the document read against the suites it names; the measured scan that produced its scope numbers.
- **Proof classification:** machine-verifiable for the gates; the document itself is reviewed.
- **Required checks:** `npm run build`; `npm run check`; `npm test`; `npm run test:dist`; `python3 scripts/validate-governance.py`.
- **Rollback/containment:** `git revert -m 1`. Documentation only; reverting removes the file and touches nothing that renders.
- **Issue links:** none. Owner feedback, 2026-08-03.
- **Evidence after completion:** Gates: build exit 0, check exit 0 with 0/0/0, 104/104 unit tests, 10/10 dist tests, validator 44/44 — all rerun after the docs landed.

  **The scope numbers in this card were measured, not estimated.** A scanner over the built output counted 925 non-breaking spaces already present, 156 forward-pointing pairs still untied inside runs long enough to wrap, and 46 places where a protected phrase can still split. Two earlier versions of that scanner printed confident numbers that were wrong, because they compared literal U+00A0 characters that are invisible in an editor; the version the numbers come from contains no non-ASCII literal at all and builds every special character from its code point.
