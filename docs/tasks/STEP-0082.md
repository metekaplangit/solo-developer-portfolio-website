# Task Card — STEP-0082

- **ID:** STEP-0082
- **Type:** feature (content / release state)
- **One outcome:** The Magic Notes pages present a released product — a Mac App Store button, a price, a release date and a truthful `offers` block — because the app is now live.
- **Feedback:** owner, 2026-08-17 — "my magic notes app live, update the website accordingly", with the listing URL.
- **Why now:** it is the exact next step STATUS has been holding since STEP-0070: *"the Magic Notes store link, price and release date once the app is accepted"*. The trigger has fired.
- **What it actually was:** STEP-0069 and STEP-0070 built the two Magic Notes pages ahead of the release and pinned them as deliberately unclaimed — `status: in-development`, `storeLinks: []`, no `price`, no `releaseDate`. Three tests held that state on purpose, and the product page rendered "Not yet available — check back soon." The app was accepted and published on **2026-08-16**, so those pins now assert the opposite of the truth, and a visitor sent from the store's own support link lands on a page saying the app cannot be had.
- **The facts, and where each came from:** read from Apple's own lookup endpoint for id `6797499171` on 2026-08-17, not from the marketing page: store title **Magic Notes Calculator**, seller **Mete Kaplan**, **Free** (`price` 0.0 USD), version **1.0.2**, first release **2026-08-16**, category Productivity, **macOS 15.0 or later**, 4+. The site keeps calling the product **Magic Notes** — the same split Sole Focus already lives with, whose listing is titled "Sole Focus Pomodoro Timer" while the site says "Sole Focus". The store title carries search keywords; the product's name is the product's name.
- **Not claimed:** no "no in-app purchases" line, which Sole Focus's sign-off carries. The listing exposes no in-app-purchase list either way, and the lookup endpoint has no field for it, so the absence of a badge is not evidence. Free is verified; the rest is not, and stays unwritten.
- **Avoid:** touching `featured`. Sole Focus holds the home spotlight, and `index.astro` gives the hero a hue only while exactly one product is featured — flipping this flag would silently swap the whole home page to a different product. That is a design decision, not a release fact, and it is not in this packet.
- **Approach:** frontmatter only, plus the sign-off paragraph the page ends on. `status` → `released`, the verified Mac App Store link at `status: available`, `price: "0"`, `releaseDate: 2026-08-16`, `lastUpdated: 2026-08-17`. No component changes: `hasStoreLinks`, `DownloadButton`, `FactsLine`, the `Released` meta pair and the `offers` builder all already read these fields, which is what STEP-0069 built them to do.
- **Acceptance criteria:** (1) `/apps/magic-notes/` renders a Mac App Store button and no "Not yet available". (2) The page emits an `offers` block naming price `"0"` and the verified listing URL. (3) The badge reads `Released`. (4) The three content pins that asserted non-release are replaced by pins on the released facts, not deleted. (5) Both new assertions seen red against the v0.48.1 build first. (6) `/privacy/magic-notes/` is untouched — the URL inside the shipped binary cannot move.
- **Non-goals:** `featured` and the home spotlight; a maker's note (still needs the maker's own words); STEP-0033's updates/release-notes block, whose trigger is a *second* version of a shipped app, not a first release.
- **Files:** `src/content/products/magic-notes.md`, `src/content/products.content.test.ts`, `tests/dist.test.ts`, `docs/STATUS.md`, `docs/ROADMAP.md`, `docs/CHANGELOG.md`.
