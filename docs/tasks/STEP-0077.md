# Task Card — STEP-0077

- **ID:** STEP-0077
- **Type:** feature (an app icon beside its name in the catalog)
- **One outcome:** Every product band shows the product's icon beside its name, so the catalog identifies a product the way every other page on the site does.
- **Feedback:** `2026-08-03-apps-page-icons-beside-names` — "I want icon and names in the apps/games page. Not just names." The owner boxed the "Sole Focus" heading and labelled it NAME.
- **Why now:** it is the page the nav points at, and the last of the five items reported in that sitting.
- **What it actually was:** the product page and both policy pages already used the shared `.identity` lockup — icon, then name, on one line (DESIGN.md, Identity Lockup, STEP-0061). `ProductBand` was the one surface that named a product without ever showing it, so the catalog and the home page were the two places a visitor met a product with no icon at all.
- **Approach:** use the same lockup rather than inventing a second one. `ProductAvatar` at 56px, the shared `.identity` wrapper, and the over-line kept **above** it so the icon aligns with the name it belongs to instead of with a 12px label. The icon links to the same page as the title, so it is passed `redundant`: mouse-clickable, but out of the tab order and the accessibility tree rather than a second stop announcing a destination the title already announced.
- **Avoid:** putting the over-line inside the lockup, which would align the icon to "01 — APP · RELEASED" instead of to the name. Avoided too: a second icon link in the tab order, and a bespoke lockup that could drift from the three surfaces already using the shared one.
- **A spacing detail worth naming:** the `margin-bottom` moved from `.band-name` to the lockup. Left on the name it sat inside the flex row, so the icon's own box grew by it and the gap under the block came from two places at once — the same doubling STEP-0075 removed above the gallery (CHECKLIST W2).
- **Acceptance criteria:** (1) both bands on `/apps/` show a 56px icon beside the name, vertically centred against it rather than above it. (2) The same holds on the home page. (3) It holds at 390px. (4) No image fails to load and no console error appears. (5) The icon adds no keyboard stop.
- **Non-goals:** icon sizes on the product and policy pages, and the ProductCard component, which is not used on either page.
- **Files:** `src/components/ProductBand.astro`, `docs/STATUS.md`, `docs/ROADMAP.md`, `docs/CHECKPOINTS.md`, `docs/CHANGELOG.md`.
- **Evidence method:** the built pages rendered in a headless browser at 1440px and 390px, icon presence, size, alignment and load state read from the DOM, plus full-page captures.
- **Proof classification:** machine-verifiable measurement, plus a rendered comparison.
- **Rollback/containment:** `git revert -m 1`. One component; the lockup and avatar it uses are unchanged and shared.
- **Required checks:** `npm run build`; `npm run check`; `npm test`; `npm run test:dist`; `python3 scripts/validate-governance.py`.
- **Issue links:** none. Owner feedback, 2026-08-03.
- **Evidence after completion:** Gates: build exit 0 (10 pages), check exit 0 with 0/0/0, 111/111 unit tests, 14/14 dist tests, validator 44/44.

  **Read from the rendered DOM, not from the markup.** `/apps/` at 1440px: both bands report `icon=true, 56px, beside=true, gap=16px, broken=false`. At 390px: both the same, gap 12px — the icon stays beside the name rather than dropping above it. Home at 1440px: the one band there reports the same. No console error, no failed request, no undecoded image on any of the three.

  **A harness bug found and fixed while proving it.** The capture script recorded failed requests across retry attempts, so a detached attempt's half-finished image loads were reported as two broken images that are present in `dist` and load fine. Errors are now cleared per attempt. Worth recording because the first run of that script produced a false failure, not a false pass.
