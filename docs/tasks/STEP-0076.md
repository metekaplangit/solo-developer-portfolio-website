# Task Card — STEP-0076

- **ID:** STEP-0076
- **Type:** fix (the two privacy cards read as one set)
- **One outcome:** The per-product policy cards on `/privacy/` are the same height and carry the same treatment, whatever the products are called.
- **Feedback:** `2026-08-03-privacy-policy-cards-no-harmony` — "these 2 boxes of privacy policies… obviously has no harmony at all. Their heights are not equal."
- **Why now:** it is the block a store reviewer scrolls to when checking that every app has a policy, and the second product only arrived last packet — the defect could not appear until there were two cards.
- **What it actually was, measured rather than judged:** **96px against 66px** at 1440px, and the two cards ended on different bottom edges. Two independent causes, both in the same rule set. `.policy-link` was a flex row with `justify-content: space-between`, so the date sat *beside* the name when both fitted on one line and *underneath* it when they did not — one component rendering two different designs depending on how long a product is called. And each card was only as tall as its own text, because the `<li>` stretched to the grid row while the link inside it did not.
- **Approach:** one treatment, then one height. `.policy-link` becomes a grid — name above, date below, always, for every product. `.policy-list > li` becomes a grid too, so the link fills the row and cards side by side stretch to match. No fixed height anywhere: the shared height is the row's, so a longer product name lengthens both cards rather than breaking the set.
- **Avoid:** a `min-height` or a fixed height on the card. It would hold today's two products level and break the moment a third has a longer name, which is the same defect with a delay. Avoided too: truncating or shortening a policy title to make it fit.
- **Acceptance criteria:** (1) the two cards are the same height at 1440px, 900px and 390px. (2) Side by side they share a bottom edge. (3) Name and date sit in the same places on both. (4) No fixed or minimum height is introduced. (5) No copy changes.
- **Non-goals:** the checklist's layout section, which STEP-0072 already delivered — this item's second half; the intro paragraph above the cards, which now meets the text rules.
