# Task Card — STEP-0059

- **ID:** STEP-0059
- **Type:** fix (content integrity / edge rewriting)
- **One outcome:** `support@metkapstudio.com` reaches the visitor as readable
  text in the HTML the live site serves, with no JavaScript required.
- **Why:** AUDIT-0009 Finding SMOOTH-0009-1. Measured 2026-08-01:
  `curl -s https://metkapstudio.com/support/ | grep -c support@metkapstudio.com`
  returned **0**, while the same page in `dist` contained the address twice.
  Cloudflare's Email Address Obfuscation rewrites it at the edge into
  `<span class="__cf_email__">` plus `/cdn-cgi/l/email-protection#33404643…`,
  decoded only by an injected `email-decode.min.js`. With JavaScript off or
  blocked, the site's only support contact did not render at all — on a site
  whose support page promises "a real person answers".
- **Prior art:** Cloudflare documents a per-element opt-out —
  `<!--email_off-->address<!--/email_off-->` — alongside the zone-wide dashboard
  toggle (Security Settings / Scrape Shield → Email Address Obfuscation) and the
  API `PATCH email_obfuscation: "off"`. (Cloudflare WAF docs, *Email Address
  Obfuscation*; checked 2026-08-01.)
- **Avoid:** the dashboard toggle alone. It fixes the symptom but lives outside
  this repository, cannot be proved by any check the project owns, and silently
  regresses if the zone is ever reconfigured. The in-repo markers are inert
  comments when the feature is off, so they compose with the toggle rather than
  competing with it.
- **Approach:** one component, `src/components/SupportEmail.astro`, wrapping a
  **slot** in the marker pair. Every place the address reaches HTML now goes
  through it.

## Two things the implementation had to get right

**The wrapper must not render the link itself.** The first version took `label`
and `href` props and emitted the `<a>` via `set:html`. That `<a>` carried no
`data-astro-cid-*` scope attribute, so page-scoped rules stopped matching it —
caught on the About page, where `.elsewhere a { color: var(--muted) }` no longer
applied and the link rendered white against muted siblings. Measured:
`rgb(255,255,255)` where its siblings were `rgb(162,167,179)`. Wrapping a slot
keeps the `<a>` in the caller's file, and its scope with it.

**JSON-LD needs no wrapper.** The live home page serves
`"email":"support@metkapstudio.com"` inside `application/ld+json` intact — the
edge leaves it alone. `src/lib/schema.ts` is therefore unchanged, and the one
remaining unwrapped occurrence in `dist/index.html` is that entry, by design.

- **Files:** `src/components/SupportEmail.astro` (new);
  `src/pages/index.astro`, `src/pages/about/index.astro`,
  `src/pages/support/index.astro` (2 sites),
  `src/components/PolicyArticle.astro` (4 links + the retention prose).
  Seven call sites. `src/lib/site.ts` and `src/lib/schema.ts` untouched.
- **The retention statement** (`src/content/policies/global.md`) is free prose
  that names the address and is rendered as a text node, so it is wrapped as a
  whole paragraph rather than per-address.
