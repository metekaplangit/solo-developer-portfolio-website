# Task Card — STEP-0073

- **ID:** STEP-0073
- **Type:** fix (the text the wrapping rule never reached)
- **One outcome:** No page on the site can break a sentence or a name at a point that leaves the reader hanging — the checklist's T1, T2 and T4 hold everywhere, and a suite fails if they stop holding.
- **Feedback:** `2026-08-03-text-cut-in-the-middle-checklist`.
- **Why now:** the owner reported this as "in every page… this middle cut texts are everywhere", and the measurement agreed: 156 forward-pointing pairs untied in runs long enough to wrap, and 46 places a product name could split. STEP-0072 wrote the rules down; a rule nothing applies is not a rule.
- **What was actually wrong:** the mechanism has existed since STEP-0062 and most of the site bypassed it. `product.summary` was rendered raw on three surfaces (`ProductCard`, `ProductBand`, `apps/[slug]`), which is exactly the copy the owner pointed at — the Sole Focus lead breaking as "…a Pomodoro" with "timer" alone on the next line. Seven policy lists (`dataCollected`, `dataUse`, `dataNotCollected`, `thirdPartyServices`, `storedLocally`, `permissions`, `retention`) came straight out of the content file untouched; only the five `resolveSection` bodies ever met the rule. Every page's own lede — `/apps/`, `/privacy/`, `/about/`, `/404` — was literal JSX. The band facts line and `effectiveScope` were untied too.
- **The second half of it:** the rule only knew function words. "Pomodoro" is not one, so "a Pomodoro timer" bound as "a Pomodoro" and guaranteed the break fell before "timer". Named things — product names, store names, compound terms — now bind as units through a curated list, matched longest first so "Mac App Store" wins over the "App Store" inside it.
- **Prior art:** the phrase list is the standard remedy — bind the terms a reader holds as one word rather than guessing at grammar. `text-wrap: pretty` cannot help: Chromium, the engine the owner reads the site in, adjusts only the last four lines of a paragraph ([WebKit](https://webkit.org/blog/16547/better-typography-with-text-wrap-pretty/)).
- **Avoid:** a generic "bind any two capitalised words" rule, which would bind ordinary sentences and produce runs wide enough to overflow the 320px column. Avoided too: tying `<title>`, meta descriptions and alt attributes — none of them wraps in the page, and alt text is read aloud.
- **Approach:** apply the rule where the content is READ rather than where it is rendered — `productSummary()` in `lib/products.ts` for all three product surfaces, one `list` map in `PolicyArticle` for all seven policy lists. A fourth surface cannot then forget. Literal page ledes call `tie()` directly. `bindPhrases()` runs inside `tie()`, so every existing call site gained phrase protection with no new call site to remember.
- **Acceptance criteria:** (1) zero untied forward-pointing pairs in wrappable runs across all 10 built pages. (2) Zero splittable protected phrases. (3) No bound run longer than 30 characters. (4) All three enforced by `npm run test:dist`, each seen red against deliberately broken output. (5) No copy reworded.
- **Non-goals:** the layout and whitespace rules the checklist also states — those are read by a person and are worked as STEP-0075..0077; the screenshot transcript (STEP-0074).

  **A trap worth recording, and now recorded in AI_WORKFLOW.md.** `npm run build` did **not** pick up a change to `src/lib/typography.ts`. The satteri plugin imports it through `astro.config.mjs`, and a stale `node_modules/.vite` cache kept serving the previous module — the build succeeded, the unit tests passed on the new code, and the built pages were produced by the old code. It looked exactly like a logic bug, and roughly twenty minutes went into chasing one. `rm -rf node_modules/.vite node_modules/.astro .astro` before a build that changes anything loaded by the config.
