# Task Card — STEP-0064

- **ID:** STEP-0064
- **Type:** fix (build integrity — dependency provenance)
- **One outcome:** Every package the build imports is declared, and the dependency gate `docs/SECURITY.md` states is actually met.
- **Feedback:** AUDIT-0010 (whole-project evaluation, 2026-08-01).
- **Why now:** `astro.config.mjs` imports `@astrojs/markdown-satteri` and `src/lib/satteri-tie.ts` imports a type from `satteri`. Neither was in `package.json` — both resolved only because they are dependencies **of** astro (`package-lock.json`, `node_modules/astro` → `@astrojs/markdown-satteri@0.3.2`). Any astro release that drops or renames either breaks the build with no warning, and the failure is worse than a build error would suggest: `satteri-tie` is what applies the wrapping rule (STEP-0062) to every Markdown body, so a variant of this failure stops the rule silently. Separately, `npm audit` reported 11 advisories (3 low, 3 moderate, 5 high) while `docs/SECURITY.md` stated "`npm audit` must be clean at merge" in two places. The project's own stated gate was failing.
- **Prior art:** Dependency *provenance* — what is in the software and how it got there — is now a first-class supply-chain check ([Cloudsmith 2026 supply-chain guide](https://cloudsmith.com/blog/the-2026-guide-to-software-supply-chain-security-from-static-sboms-to-agentic-governance); [How to Evaluate an npm Package, 2026](https://blog.gaborkoos.com/posts/2026-05-29-How-to-Evaluate-an-npm-Package-2026-Edition/), read 2026-08-01). Importing a transitive dependency directly is the case both name.
- **Avoid:** `npm audit fix --force`. Verified by dry-run 2026-08-01 — it installs `@lhci/cli@0.1.0`, a breaking downgrade that would take out the accessibility gate in `.github/workflows/deploy.yml`. Confirmed after the fact: `@lhci/cli` is still `0.15.1`.
- **Avoid:** pinning satteri to an exact version. It has to stay compatible with whatever `astro` resolves.
- **Approach:** declare both packages at caret ranges matching what the lockfile already resolved, run the plain `npm audit fix`, and rewrite the gate in `docs/SECURITY.md` to the one that is both true and meaningful — `npm audit --omit=dev` — with the residual dev-only advisories named and reasoned.
- **Design decision — `dependencies`, not `devDependencies`.** `satteri-tie.ts` is imported by `astro.config.mjs`, which runs for every build.
- **Design decision — the gate becomes `--omit=dev`, not "clean".** The old wording was aspirational: it could not be met without breaking the a11y gate, so it was being ignored, which is worse than a narrower gate that is actually enforced. Nothing dev-only reaches `dist`, so nothing dev-only reaches a visitor.
- **Design decision — the astro 7.0.5 → 7.1.6 bump is kept, not reverted.** Adding a dependency makes npm re-resolve the tree, and `^7.0.0` permits it. Reverting the lockfile would only mean the next `npm install` did the same thing silently, which is the exact class of problem this card exists to remove. Taken deliberately and proved below instead.
- **Acceptance criteria:** (1) Every bare import in `astro.config.mjs` and `src/lib/*.ts` maps to a declared dependency. (2) `npm audit --omit=dev` exits 0. (3) Residual advisories are dev-only and named in `docs/SECURITY.md` with the reason they stay. (4) `@lhci/cli` still `0.15.1`, so the a11y gate survives. (5) Built output unchanged apart from astro's own version string.
- **Non-goals:** upgrading astro deliberately; adding a dependency-scanning CI gate (declined in AUDIT-0010 — 11 build-time-only advisories on a site that ships no JavaScript is recurring noise with no matching risk, and the project retired its cadence for that reason).
- **Files:** `package.json`, `package-lock.json`, `docs/SECURITY.md`.
- **Evidence method:** full `dist` rebuilt at astro 7.0.5 and snapshotted, then rebuilt after the change and compared character by character with `difflib.SequenceMatcher` across all 8 routes, plus `diff -rq` over `dist/_astro`.
- **Proof classification:** machine-verifiable.
- **Required checks:** `npm run build`; `npm run check`; `npm test`; `python3 scripts/validate-governance.py`; deploy-time Lighthouse a11y gate (≥0.95).
- **Rollback/containment:** two manifest lines and a lockfile; `git revert -m 1`.
- **Issue links:** AUDIT-0010. No GitHub issue.
- **Evidence after completion:** Both packages declared; all four bare imports (`astro/config`, `@astrojs/sitemap`, `@astrojs/markdown-satteri`, `satteri`) now resolve to declared dependencies. Production advisories **3 → 0** (`npm audit --omit=dev` exit 0, was 1 moderate + 2 high). Total advisories 11 → 5, all remaining dev-only under `@lhci/cli`. `@lhci/cli` unchanged at 0.15.1. Gates: build exit 0, check 0 errors / 0 warnings / 0 hints, 83/83 tests, validator 44 checks passed.

  **A measurement error of my own, caught by re-measuring.** An intermediate reading claimed the non-breaking space count had jumped 287 → 1748. It had not: the literal U+00A0 in a `python3 -c` argument was mangled by the shell, so the second count was counting something else. The real count never moved. Recorded because the wrong number nearly became the reason to abandon a correct change — the fix was to put the character in a heredoc instead of a shell-quoted argument.

Not caused by this card and not reproduced since — recorded here because the same failure on the deploy runner would break every image on the site, and this is the only written trace of it.
