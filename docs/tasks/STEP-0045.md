# Task Card — STEP-0045

- **ID:** STEP-0045
- **Type:** feature (UI — design-system identity swap)
- **One outcome:** The whole site changes identity in one move — near-black stage, achromatic studio chrome, product hue available to any band, three button heights, softer radii, a wider rail — and `DESIGN.md` / `docs/UI_DESIGN.md` record the three named rules that were replaced and why.
- **Why now:** Owner selected design option **E ("Spectrum")** from the 2026-07-31 mockup run and asked that every page be updated in harmony. Second card of six (STEP-0044..0049). The token layer is the only place where one change re-skins all eight routes at once, which is what makes this packet shippable on its own rather than leaving the site half-converted.
- **Acceptance criteria:** (1) `:root` carries the Spectrum tokens; no component hardcodes a colour. (2) All eight routes render coherently. (3) Every token pair clears WCAG AA, proved by computation. (4) `theme-color` and `site.webmanifest` match the new ground. (5) 0 horizontal overflow across the width matrix. (6) `DESIGN.md` and `docs/UI_DESIGN.md` updated.
- **Rules replaced (recorded, not re-litigated):**
  - **Never-Black → Near-Black Floor.** Ground `#16171b` → `#08090c`. Same intent, lower floor: research puts white-on-black halation and OLED black crush at linear value ~5, which is the real reason the old rule existed. `#08090c` is ~8 — dark enough for a full-bleed poster band, above the smearing threshold. Option E's own `#050507` sat exactly on the floor with no margin on the OLED Macs this audience uses, so the ground was raised three values from the approved mockup. Visually indistinguishable at a glance.
  - **One Voice → One Voice Per Band.** A single site-wide accent is what made the previous design read as a template. The site is now achromatic; each product band carries exactly one hue, its own.
  - **One Height → One Height Per Set.** Three heights (2.25 / 2.75 / 3.25rem), one per group; a one-off height on a single button is the named failure.
- **Design decision — the studio mark keeps its own colour:** the nav/favicon mark does not take a product's hue. With one product that would read fine; with three it is arbitrary. Hue is band-scoped only.
- **Element declined — a persistent Download pill in the nav** (present in the option E mockup at desktop width). The narrow-screen nav row is already at its width limit: review-0001 OPP-01 measured "About" falling entirely off-screen at 390px, and the current one-row-of-four layout exists to fix exactly that. A fifth element reintroduces the defect the current Nav was built to remove. The download stays in the hero and the product bands.
- **Non-goals:** any page's structure (STEP-0046..0048); a light theme; the favicon/app-icon artwork and the OG image; cross-route alignment (STEP-0049).
- **Files:** `src/styles/global.css`, `src/layouts/BaseLayout.astro`, `src/components/Footer.astro`, `src/components/DownloadButton.astro`, `public/site.webmanifest`, `DESIGN.md`, `docs/UI_DESIGN.md`.
- **Evidence method:** computed contrast table (exit code) + per-width overflow sweep in a contained browser + live inspection of every route.
- **Proof classification:** machine-verifiable + manual-runtime (measured).
- **Required checks:** `npm run build`; `npm run check`; `npm test`; validator; deploy-time Lighthouse a11y gate (≥0.95).
- **Open item carried forward:** the brand mark (`public/favicon.svg` and the icon/OG set) is still periwinkle and is now the only chromatic element in the chrome. Left deliberately — regenerating the mark and every derived icon is its own outcome, not a token change. Raise at STEP-0049.

Shipping a check that cannot run would be a false green. The sweep was performed in a contained browser instead and is recorded below; accessibility scoring remains the deploy-time gate.
